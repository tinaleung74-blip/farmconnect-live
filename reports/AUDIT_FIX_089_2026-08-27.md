# Fix pass for the six pre-test findings

## Status

Implemented locally. Migration 089 is prepared, NOT executed by the agent. No production records were changed; no commit, push or deployment was made. Migration 088 was left unchanged.

## Fixes

1. Mission checklist entries now have real checkboxes. Unchecked items are sent as false. PASS requires all displayed required entries; the existing mission backend still validates the required catalog/task checklists.
2. Returned reports restore health, checklist answers, feed usage, remaining-feed value and photos. Missing historical health is unselected, never automatically PASS. Historical remaining feed without a stored numeric value must be entered explicitly.
3. After sending a task, no next task is silently opened. Selecting a task always invokes its draft initializer. Switching tasks while a submission is in flight is blocked.
4. Diary image arrays fall back to the legacy scalar image when empty. Signing failure raises a visible retryable diary error rather than silently hiding the evidence.
5. SQL 089 removes the own-object update policy and adds restrictive UPDATE/DELETE policies for authenticated clients on the evidence bucket. Photos become append-only; corrections require new objects. Service-role/DB-owner maintenance is not prevented by RLS.
6. All four caretaker submit helpers (generic, paid mission, manual mission, sale) now call one owner-checked RPC. It locks the task, verifies report and existing storage objects, dispatches to the original workflow/inventory functions, and saves a request key/payload. Exact retries return the same proof; changed payload with the same key is rejected. Legacy direct submission RPC execution is revoked for browser roles, preventing bypass.

The UI reuses already-uploaded files on retry and guards concurrent clicks. Retry keys remain scoped to the open draft; after reload a committed task cannot be resubmitted because the backend checks its status. No automatic orphan-file deletion was introduced.
