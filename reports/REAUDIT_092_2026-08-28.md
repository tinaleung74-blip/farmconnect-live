# Re-audit after migration 092 — 2026-08-28

Scope: focused source audit of support delivery, initialization, reply authorization, and KYC consent integration. No production writes, no application fixes, no push. This is not a complete live end-to-end certification.

## Confirmed source findings

### 1. P2 — Browser can supply a message attributed to KaFarm

Evidence: `database/applied/092_kyc_and_support_state_guards.sql:39-65,534`; `lib/backend/support-chat.ts`, saveKaFarmSupportMessage.

The authenticated owner of a support session is allowed to call kafarm_support_send_message with arbitrary p_body. The function saves it with sender_role='kafarm' and system-looking source metadata. Ownership prevents writing to someone else's chat, but does not establish that the reply was actually generated by trusted application logic.

ELI5: Sarili mong usapan lang ang puwede mong sulatan, pero puwede mong palabasing si KaFarm ang nagsabi ng isinulat mo. This can corrupt the credibility of support history; it does not itself approve a payment or change a balance.

Proposed fix: generate and persist replies in trusted backend logic based on the saved user message. Do not trust arbitrary reply text from the browser. Preserve owner isolation and add reply idempotency. Test that a customer cannot author a system-role message directly.

### 2. P2 — Initial Support load failure leaves the page disabled

Evidence: `lib/support-conversation.tsx:35-57,103`.

Initialization sets ready=true only after profile/draft/session loading succeeds. Its catch only sets an error. The effect reruns on role changes, not network recovery; polling only starts when a session exists. An initial network error therefore leaves textarea and Send disabled until remount/reopening. Invalid saved draft JSON follows the same path and persists even across reopening.

ELI5: Naputol ang internet habang binubuksan ang Support. Kahit bumalik ang internet, hindi bumabalik ang Send button sa page na iyon.

Proposed fix: provide a safe initialization retry with account revalidation. Separate corrupt-draft recovery from network failure; preserve recoverable text and never silently resend an uncertain operation under a new key.

## Not yet established

However, the complete live run_kyc_system_checks definition and relevant table triggers are not available in this source audit. Do not call this a confirmed consent bypass without checking those dependencies. Next check: inspect those live definitions read-only, then test first submission and direct RPC submission on an isolated database.
